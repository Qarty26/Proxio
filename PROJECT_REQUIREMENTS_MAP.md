# Proxio - Mapare Cerinte Proiect

Acest document mapeaza cerintele proiectului la implementarea existenta din repo. Pentru fiecare cerinta sunt trecute: ce este adaugat, unde se afla in cod, cum functioneaza si cum poate fi demonstrat.

## Cum rulezi proiectul pentru demo

| Scop | Comanda / URL | Observatii |
| --- | --- | --- |
| Pornire full stack | `docker compose up --build` din radacina repo-ului | Porneste PostgreSQL, Redis, backend, backend replica, gateway, frontend, discovery, config, notification, Prometheus si Grafana. |
| Reset baza de date | `docker compose down -v --remove-orphans` | Sterge volumul PostgreSQL, util cand schimbi branch-ul sau vrei date/schema fresh. |
| Frontend | <http://localhost:5173> | React app. Apeleaza API Gateway pe `8081`. |
| API Gateway | <http://localhost:8081> | Intrarea principala pentru browser/API demo. |
| Backend direct | <http://localhost:8080> | In Docker, multe endpoint-uri directe cer `X-Internal-Token`; pentru demo foloseste gateway-ul. |
| Discovery Service | <http://localhost:8761> | Registry custom pentru servicii. |
| Config Service | <http://localhost:8888> | Catalog custom de configurari centralizate. |
| Notification Service | <http://localhost:8082> | Microserviciu separat pentru notificari. |
| Prometheus | <http://localhost:9090> | Metrici scrape-uite din servicii. |
| Grafana | <http://localhost:3000> | User/parola: `admin` / `admin`. |

## Observatii importante pentru prezentare

| Observatie | Explicatie |
| --- | --- |
| Foloseste `8081`, nu `8080`, pentru UI/API demo | In Docker, backend-ul direct are protectie interna cu `X-Internal-Token`; gateway-ul adauga tokenul automat. |
| Unele cerinte optionale sunt implementate custom | Discovery, config server, load balancing si resilience sunt implementate lightweight/custom, nu cu Eureka/Spring Cloud Config/Resilience4j. Sunt totusi demonstrabile functional. |
| UI nu are formulare pentru toate entitatile | API-ul are CRUD pentru toate entitatile. UI-ul acopera fluxurile principale: auth, user management si products. Pentru restul se pot folosi request-urile din [`backend/requests`](backend/requests). |
| Coverage exact trebuie generat | Testele exista, dar daca profesorul cere procent numeric, ruleaza coverage din IDE sau configureaza Jacoco explicit. |
| Refresh dinamic config, tracing, HTTPS si micro-frontends nu sunt implementate | Sunt cerinte bonus/maxim; nu trebuie prezentate ca fiind facute. |
